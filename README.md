# thundo — AI 콘텐츠 자동화 파이프라인 & 포트폴리오 웹

혼자 운영하는 AI 콘텐츠 자동화 시스템과, 그 결과물을 보여 주는 웹 애플리케이션의
**공개 스냅샷**입니다.

```
blog-publisher/   에이전트 32마리가 협업하는 한국어 블로그·쇼츠·카드뉴스 자동발행 파이프라인
thundorun/        Next.js 15 + Supabase 포트폴리오 사이트 + 운영 대시보드
```

## 이 저장소에 대해

개발은 비공개 저장소에서 하고, **공개할 수 있는 파일만 골라 특정 시점마다 스냅샷으로**
이곳에 올립니다. 그래서 커밋 로그는 `snapshot YYYY-MM-DD — 설명` 형태이고, 개발 과정의
커밋 하나하나가 남아 있지는 않습니다.

이렇게 하는 이유는 원본 저장소의 이력에 제3자(거래처) 운영 정보와 개인 정보가 섞여 있어서
그대로 공개할 수 없기 때문입니다. 허용 목록에 있는 파일만 복사되고, 발행 직전 자동 검사가
크리덴셜·거래처 식별자·개인 이메일·차단 경로를 잡아냅니다. 검사에 하나라도 걸리면 발행이
중단됩니다.

**바로 실행되는 상태는 아닙니다.** 운영 설정·크리덴셜·런타임 상태는 빠져 있습니다.
설계와 구현을 읽는 용도로 봐 주세요.

## blog-publisher — 무엇을 하는가

매일 정해진 시각에 주제를 모으고, 초안을 쓰고, 검사를 통과한 글만 발행합니다.
사람이 개입하지 않아도 돌아가는 것을 목표로 만들었고, 품질은 **결정론 게이트**가 지킵니다.

```
수집 → 주제 선정 → 작가 배정 → 초안 → 게이트 16종 → 검증자 5명 → 발행 → 감사로그
```

핵심은 LLM 을 믿지 않는 구조입니다.

- **결정론 게이트 16종** — 중복·길이·금지어·링크 생존·AI 티·출처 세탁·정보 밀도·헤징
  밀도·내부 재진술·니치 적합성·렌더 적합성·SEO·소스 사실 대조. 전부 규칙 기반이라
  같은 입력에 같은 판정이 나옵니다. `scripts/gates/`
- **검증자 5명** — 사실·SEO·편집·표절·렌더를 각각 보는 LLM 검증자. **차단권만** 있고
  글을 고치지는 못합니다.
- **자가발전 3권분립** — 제안·채점·적용을 분리하고, 성능이 나아진 변경만 채택합니다.
  적용기는 게이트·감사·시드 파일을 건드리지 못하게 막혀 있습니다. `scripts/evolve/`
- **감사 로그** — sha256 해시 체인 append-only. `scripts/audit/`

같은 파이프라인에서 유튜브 쇼츠(`scripts/shorts/`, `scripts/shorts-curiosity/`)와
인스타그램 카드뉴스(`scripts/cardnews/`)도 만듭니다. 카드뉴스의 고전문학 인용은
LLM 판단이 아니라 **원문 대조**로 검증합니다 — 인터넷에는 그 책에 없는 문장이 그 책 것으로
떠돌고, LLM 은 거기에 출처까지 그럴듯하게 붙이기 때문입니다.

## thundorun — 무엇을 하는가

발행된 글을 보여 주는 포트폴리오 사이트이자, 파이프라인을 들여다보는 운영 대시보드입니다.

- Next.js 15 App Router · Supabase · next-auth
- 서버 컴포넌트에서만 DB 를 읽고, 클라이언트로는 anon 키 경로를 만들지 않습니다
- 관리자 API 는 미들웨어와 핸들러에서 이중으로 막습니다
- 순수 CSS 디자인 시스템(`DESIGN.md`) — Tailwind·UI 라이브러리 없음
